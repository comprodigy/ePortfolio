Travlr Getaways

CS 465 Client/Server Development. MEAN stack trip app. Enhanced for databases. Outcomes 1, 4, and 5.

What it was

The customer site lists trips. An Angular admin app was meant to add and update them through an Express API backed by MongoDB. I did not finish the security chapter. On the module7 branch the trip schema, trip reads and writes, a user model, and a Passport strategy existed. Login was wired in the router but not implemented. authenticateJWT was named on POST /trips and never defined. The user model was registered twice, once before the password methods were attached. Failed writes returned an err that was never declared. Update returned 201. Trip codes were indexed but not unique.

What changed

  • The user model is registered once, after setPassword, validPassword, and generateJWT. Passwords stay as hash and salt. A role field is admin or customer.
  • register and login both return a JWT. Writes on trips require that token and an admin role. Reads stay public so the customer site still works.
  • Trip code is unique. start and resort are indexed.
  • Handlers use try/catch. Find-by-code is findOne. Update returns 200 and does not change the code.
  • GET /api/reports/trips-by-resort aggregates trip counts by resort for a logged-in user.

Narrative

I picked this artifact because it is the only full database project I have from the program, and the unfinished auth was an honest gap rather than something I had to invent. The enhancement stays on the data layer. I did not rebuild the Angular screens.

The hard part was not Mongo. It was code that looked finished and was not. The login route, the JWT middleware, and the user methods were all present in different files and did not connect. Registering the model before the methods meant setPassword could be missing at runtime. Leaving reads public and locking writes was the trade-off I wanted to show. A public trip list is the product. An open POST is not.
