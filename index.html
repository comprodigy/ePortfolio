Professional self-assessment

I selected the Computer Science course as a hobbyist programmer that had been programming for over ten years, wanting a degree to attest to what I knew. I did not anticipate learning what I did throughout this course. I was a decent programmer to begin with, but I wasn’t a software developer. This coursework taught me things such as the software development lifecycle, Big O Notation, and different software stacks that I had never considered before in my limited scope of development.

These artifacts as well as the additional coursework helped to refine me as a software developer. Design classes taught me to move from a requirements document to modular code. Other courses taught me security practices like “least privilege” and to invalidate everything until its proven valid, as opposed to looking for reasons to invalidate a request. Software Automation taught me how to properly test my codebases through rigid, fixed tests that are easily enough developed and repeatable.

The five outcomes in this course are job skills that I am claiming. Collaboration and decision support show up as data a non-developer can use. Professional communication in this site, with the code review and narratives. Data Structures and Algorithms are a conscious choice of structure and stated trade-offs. Software Engineering and Databases are layered design, a repo, a schema, indexes and tools used the way a real team would. Security is vital, and this is demonstrated with hashed credentials, sessions, validation and the right of least privilege.

I present three artifacts demonstrating these five outcomes. Compustocker is my software design piece. This was created in CS 360, a mobile inventory app restructured so the Activity is no longer the application. This makes the code base more versatile, easily adapted to other platforms with the same code. The contact service is the algorithm piece. Created in CS 320, this stores data in a Hashmap which was already efficient, and expands on it by checking the UniqueIDs vs a livemap. Travlr is a full-stack webpage made in CS 465. This application utilizes the MEAN stack, leveraging Angular, Express, MongoDB and Node.js. Through this artifact I implemented authentication, tokens, JWT and fixed redundant errors throughout. Through these artifacts I demonstrated my ability to not only make full, real applications, but my ability to refactor existing code with new skills I learned along the way.

I am targeting junior backend or mobile roles. Employers in that lane expect clean structure, tests, efficient data access, and not storing secrets in plaintext. This portfolio is the evidence for those interviews.
